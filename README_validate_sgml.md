# SGML Validator

Python-скрипт для проверки корректности открытия и закрытия тегов в SGML/XML файлах.

## Возможности

- ✅ Проверка парности открывающих и закрывающих тегов
- ✅ Обнаружение незакрытых тегов
- ✅ Обнаружение закрывающих тегов без открывающих
- ✅ Обнаружение неправильного порядка закрытия тегов
- ✅ **Обнаружение опечаток в именах тегов:**
  - Проверяет, существует ли тег в списке известных DocBook/HTML тегов
  - Предлагает похожие теги при обнаружении опечаток (алгоритм Левенштейна)
  - Примеры: `<lital>` → подсказка `literal`, `<uliiink>` → подсказка `ulink`
- ✅ **Проверка правил использования `<title>`:**
  - Не может быть два `<title>` подряд
  - `<title>` должен быть только внутри разрешённых тегов (`sect1`, `sect2`, `sect3`, `sect4`, `sect5`, `figure`, `table`, `simplesect` и др.)
  - В каждом родительском теге может быть только один `<title>`
- ✅ Показ **всех** ошибок сразу (не по одной)
- ✅ Поддержка DocBook SGML пустых элементов (`colspec`, `xref`, `imagedata` и др.)
- ✅ Игнорирование entity references (`&mdash;`, `&nbsp;` и т.д.)
- ✅ Игнорирование комментариев и деклараций

## Использование

### Проверка одного файла

```bash
./validate_sgml.py путь/к/файлу.sgml
```

Пример:
```bash
./validate_sgml.py tantor/contrib/vector/vector.sgml
```

### Проверка всех файлов в директории

```bash
./validate_sgml.py путь/к/директории
```

Пример:
```bash
./validate_sgml.py tantor/contrib
```

По умолчанию проверяются все файлы с расширением `.sgml`.

### Проверка файлов по паттерну

```bash
./validate_sgml.py путь/к/директории 'паттерн'
```

Примеры:
```bash
./validate_sgml.py tantor '**/*.sgml'
./validate_sgml.py doc 'src/**/*.sgml'
```

## Коды возврата

- `0` - все файлы валидны (или файл валиден)
- `1` - найдены ошибки валидации

Это позволяет использовать скрипт в CI/CD:
```bash
./validate_sgml.py tantor/contrib && echo "Все файлы корректны!" || echo "Найдены ошибки!"
```

## Обнаружение опечаток в тегах

Скрипт проверяет, существует ли каждый используемый тег в списке известных DocBook и HTML тегов. При обнаружении неизвестного тега:

1. **Показывает ошибку** с указанием строки и имени тега
2. **Предлагает похожие теги** используя алгоритм расстояния Левенштейна

### Примеры обнаружения опечаток:

```xml
<para>
  Текст с <lital>опечаткой</lital>  <!-- ❌ ОШИБКА: Неизвестный тег 'lital'. Возможно, вы имели в виду: literal -->
</para>

<uliiink url="...">Ссылка</uliiink>  <!-- ❌ ОШИБКА: Неизвестный тег 'uliiink'. Возможно, вы имели в виду: ulink -->
```

### Известные теги

Скрипт знает о **100+ тегах** из DocBook и HTML, включая:
- Структурные: `sect1-5`, `refsect1-3`, `chapter`, `appendix`, `section`
- Блочные: `para`, `formalpara`, `note`, `warning`, `programlisting`
- Списки: `itemizedlist`, `orderedlist`, `listitem`, `variablelist`
- Таблицы: `table`, `informaltable`, `tgroup`, `row`, `entry`
- Встроенные: `emphasis`, `literal`, `quote`, `command`, `filename`
- Ссылки: `link`, `ulink`, `xref`
- И многие другие...

## Правила валидации для `<title>`

Скрипт проверяет специальные правила для тега `<title>`:

### 1. Два `<title>` подряд запрещены
```xml
<sect1>
  <title>Первый заголовок</title>
  <title>Второй заголовок</title>  <!-- ❌ ОШИБКА -->
  ...
</sect1>
```

### 2. `<title>` должен быть только внутри разрешённых тегов
Разрешённые родительские теги:
- `sect1`, `sect2`, `sect3`, `sect4`, `sect5` - секции документа
- `refsect1`, `refsect2`, `refsect3` - reference секции (для документации API)
- `section`, `chapter`, `appendix`, `preface` - структурные элементы
- `figure`, `table`, `example` - элементы с заголовками
- `simplesect` - простые секции
- `formalpara` - параграфы с заголовками

```xml
<para>
  <title>Заголовок</title>  <!-- ❌ ОШИБКА: title внутри para -->
</para>
```

### 3. В каждом родительском теге только один `<title>`
```xml
<sect2>
  <title>Заголовок раздела</title>
  <para>Текст...</para>
  <title>Ещё один заголовок</title>  <!-- ❌ ОШИБКА -->
</sect2>
```

## Поддерживаемые пустые элементы DocBook

Скрипт знает о следующих пустых элементах DocBook, которые не требуют закрывающих тегов:

- `colspec`, `spanspec` - определения колонок в таблицах
- `imagedata` - данные изображений
- `xref` - перекрёстные ссылки
- `anchor` - якоря
- `footnoteref` - ссылки на сноски
- `indexterm` - термины индекса
- `areaspec`, `co` - области и выносные обозначения

## Ограничения

1. Скрипт проверяет только структуру тегов (открытие/закрытие), но не валидирует:
   - Правильность атрибутов
   - Соответствие DTD или схеме
   - Правильность entity references

2. Скрипт обрабатывает теги построчно. Теги, разбитые на несколько строк, обрабатываются корректно, если их атрибуты находятся до закрывающей `>`.

3. **Файлы-фрагменты** (для включения в другие документы) также проверяются:
   - Файлы из папок `replace_part_sgml/`, `insert_part_sgml/`
   - Файлы с префиксами `replace_*`, `func_*`, `add_*`
   - Такие файлы могут иметь ошибки структуры (незакрытые теги, отсутствие родителя для `<title>`), что нормально для фрагментов

## Решённые проблемы

Этот скрипт был создан как альтернатива расширению XML для Cursor/VSCode, которое:
- ❌ Показывало ошибки по одной (пока не исправишь - не видно следующих)
- ❌ Требовало сложной настройки для игнорирования entity references
- ❌ Не поддерживало DocBook пустые элементы "из коробки"

Данный скрипт решает все эти проблемы и показывает все ошибки сразу! ✨
