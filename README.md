# SGML Validator

Python-скрипт `validate_sgml.py` для проверки корректности SGML/XML файлов с поддержкой DocBook.

## Состав проекта

```
validate_sgml/
├── validate_sgml.py          # Основной скрипт валидации
├── README_validate_sgml.md   # Подробная документация скрипта
│
├── graph_sect.py             # Скрипт визуализации структуры sect-тегов
├── README_graph_sect.md      # Документация graph_sect.py
│
├── README.md                 # Этот файл
└── .gitignore
```

## Требования

- Python 3.7+
- Стандартная библиотека Python (внешние зависимости не требуются)

## Быстрый старт

Сделайте скрипты исполняемыми (один раз):

```bash
chmod +x validate_sgml.py graph_sect.py
```

### Проверка одного файла

```bash
./validate_sgml.py path/to/file.sgml
```

### Проверка всех `.sgml` файлов в директории

```bash
./validate_sgml.py path/to/directory/
```

### Проверка по произвольному паттерну

```bash
./validate_sgml.py path/to/directory '**/*.sgml'
```

## Возможности

- Проверка парности открывающих и закрывающих тегов
- Обнаружение незакрытых тегов и закрывающих тегов без открывающих
- Обнаружение неправильного порядка закрытия тегов
- Обнаружение опечаток в именах тегов с подсказками (алгоритм Левенштейна)
- Правила для тега `<title>` (запрет двойного `<title>`, проверка родителя, единственность)
- Проверка непарных кавычек в атрибутах
- Проверка текста без `<para>` внутри блочных контейнеров (`sect1`–`sect5` и др.)
- Поддержка пустых элементов DocBook (`colspec`, `xref`, `imagedata` и др.)
- Игнорирование комментариев, деклараций и entity references
- Показ всех ошибок сразу, а не по одной

Подробнее — в [`README_validate_sgml.md`](README_validate_sgml.md).

## Пример вывода

```
❌ vector.sgml: Найдено ошибок: 3
────────────────────────────────────────────────────────────────────────────────
  Строка    4: Больше одного <title> внутри <sect1> (начало на строке 2). <title>
  Строка   29: Неизвестный тег 'lital'. Возможно, вы имели в виду: literal <lital>
  Строка   84: Закрывается </sect2>, но внутри есть незакрытый <note> (открыт на строке 70) <sect2>
```

## Коды возврата

- `0` — все файлы валидны
- `1` — найдены ошибки валидации

Подходит для использования в CI/CD:

```bash
./validate_sgml.py docs/ && echo "OK" || echo "Найдены ошибки"
```

## Интерактивный режим (запуск через «Запустить как приложение»)

Оба скрипта (`validate_sgml.py` и `graph_sect.py`) поддерживают интерактивный режим. Он включается автоматически, если скрипт запущен **без аргументов** в терминале — например, через пункт **«Запустить как приложение»** контекстного меню файлового менеджера.

В этом режиме:

1. Скрипт спросит путь к файлу/директории.
2. Для `graph_sect.py` дополнительно спросит режим вывода (`-n`/`-c`/`-t` или Enter для обычного).
3. Выполнится как обычно.
4. **Окно терминала не закроется автоматически.** Для `validate_sgml.py`: `Enter` — повторить проверку того же пути (без повторного запроса), `Space` — выйти. Для `graph_sect.py` — нажать `Enter` для выхода.

Пример сессии:

```
================================================================
  SGML Validator
================================================================

Введите путь к файлу или директории: docs/manual.sgml

✅ manual.sgml: Ошибок не найдено

Нажмите Enter чтобы повторить проверку.
Нажмите Space для выхода...
```

### Безопасность для CI/CD

Интерактивный режим включается только если `stdin` подключён к терминалу (TTY). В неинтерактивных средах (CI/CD, пайпы, перенаправления) скрипт без аргументов как и раньше выводит справку и завершается с кодом `1` — никакой блокировки в ожидании ввода нет.

### Что нужно для запуска через «Запустить как приложение»

Чтобы пункт «Запустить как приложение» появился в контекстном меню файла `validate_sgml.py`/`graph_sect.py`:

1. Сделайте файл исполняемым: `chmod +x validate_sgml.py graph_sect.py`.
2. В файловом менеджере включите запуск исполняемых текстовых файлов:
   - **GNOME Files (Nautilus)**: меню → Настройки → «Поведение» → «Исполняемые текстовые файлы» → «Запускать в терминале» / «Спрашивать каждый раз».
   - **Nemo / Caja / Thunar / Dolphin**: в свойствах файла или настройках предусмотрен похожий пункт «Run in Terminal».

После этого правый клик по `.py`-файлу → «Запустить как приложение» откроет терминал и запустит скрипт в интерактивном режиме.

## Дополнительный скрипт: `graph_sect.py`

Утилита для визуализации иерархии секций (`sect1`–`sect5`) в SGML-документе.

```bash
./graph_sect.py document.sgml          # обычный вывод с отступами
./graph_sect.py document.sgml --tree   # древовидная структура
./graph_sect.py document.sgml --compact
```

Подробности — в [`README_graph_sect.md`](README_graph_sect.md).
